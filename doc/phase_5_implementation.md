# Phase 5 Implementation Plan: Dashboard & UI Integration

This document outlines the detailed technical specifications and execution steps for **Phase 5** of the Multi-Agent Software Factory. Phase 5 is the final phase, focusing on wrapping the entire backend multi-agent architecture in a user-friendly frontend Dashboard. This dashboard will allow users to monitor the factory's automated progress, visually inspect the bidirectional traceability matrix, and trigger or schedule Orchestrator jobs directly from the browser.

## Current Status
- [x] **Scaffold Frontend Dashboard Application (`dashboard/`)**
- [x] **Develop Job Scheduler & Manual Trigger UI Components**
- [x] **Develop Traceability Matrix View & Agent State Monitor UI Components**
- [x] **Integrate UI with Backend Python Scripts & CSV Data Store**
- [x] **Implement & Execute Phase 5 Verification Tests**

---

## Step 1: Scaffold Frontend Dashboard Application

We will use a modern, lightweight frontend framework (e.g., React with Vite and TypeScript, or Python Streamlit for a unified stack) to serve as the control plane for the Multi-Agent Software Factory.

*   **Target Directory:** `dashboard/`
*   **Engineering Tasks:**
    *   Initialize the project structure (e.g., `npm create vite@latest dashboard -- --template react-ts` or setup a Streamlit app).
    *   Setup basic layout and tab navigation for the core views: **Home**, **Job Control**, **Traceability Matrix**, and **System Logs**.
    *   Ensure the UI application can dynamically read from `config/ProjConfig/settings.json` to locate the workspace paths and backend scripts.

---

## Step 2: Develop Job Control UI (Scheduler & Triggers)

The user requires the ability to control the factory's execution directly from the interface.

*   **Target Components:** `dashboard/src/components/SchedulerConfig.tsx`, `dashboard/src/components/ManualTrigger.tsx` (or equivalent).
*   **Engineering Tasks:**
    *   **Manual Trigger**: Build a form where a user can input a GitHub Issue/Ticket ID and click a "Run Factory" button. This action must trigger the local `triggers/run_orchestrator.py --ticket <ID>` script via a lightweight backend API or child process execution.
    *   **Auto Scheduler**: Build a UI to configure recurring cron schedules (e.g., "Run auto-triage every 4 hours"). Save this configuration to a local state file or system cron so `triggers/run_orchestrator.py --auto` executes automatically without manual intervention.

---

## Step 3: Develop Traceability & Agent Monitor UIs

The dashboard must visualize the massive amount of structured data the agents produce.

*   **Target Components:** `dashboard/src/components/TraceabilityView.tsx`, `dashboard/src/components/AgentStateMonitor.tsx`
*   **Engineering Tasks:**
    *   **Traceability View**: Build an interactive data table (or a visual Sankey diagram) that directly reads `workspace/Requirements/traceability_matrix.csv`. It should clearly display the physical links from Requirement $\rightarrow$ Architecture $\rightarrow$ Code $\rightarrow$ Tests, highlighting any missing links or failed validations in red (leveraging the logic from `scripts/report_generator.py`).
    *   **Agent State Monitor**: Parse the structured `[INFO]`, `[WARN]`, `[ERROR]` logs generated by the Orchestrator and subagents during execution. Display a live feed of the agents' current activities and explicitly flag any `logs/github_sync_errors.log` fallback issues.

---

## Step 4: Full System Integration

Connect the frontend strictly to the underlying CSV files and Python scripts without duplicating validation logic.

*   **Engineering Tasks:**
    *   Ensure the dashboard can invoke `scripts/traceability_validator.py` on demand to show the live validation exit status in the UI.
    *   Ensure the dashboard correctly serves static generated artifacts, such as the Markdown report (`workspace/Traceability_Report.md`) and any architecture diagrams.

---

## Step 5: Verification & End-to-End Testing

*   **Target Files:** `tests/test_phase5.py` (or a Playwright/Cypress suite inside `dashboard/tests/`)
*   **Test Report Archive:** `doc/test/phase5_test_report.md`
*   **Objectives:**
    1.  Verify the Dashboard successfully parses the `settings.json` configuration to find the workspace.
    2.  Simulate a click on the "Manual Trigger" and assert it correctly dispatches the `run_orchestrator.py` command.
    3.  Verify the Traceability UI component accurately loads and parses the `traceability_matrix.csv` without throwing errors, accurately reflecting the mocked Pass/Fail states.
